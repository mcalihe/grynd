# 0023 – Pläne teilen, Backup zusammenführen, strengere Prüfung

**Datum:** 2026-10-14 · **Status:** entschieden (ergänzt [0013](0013-settings-units-swipe-backup.md): Import ersetzt nicht mehr zwingend alles)

## Kontext
Bisher gab es nur das volle Backup in den Einstellungen: alle Daten als JSON-Datei, beim Import nach einer allgemeinen Rückfrage komplett ersetzt, ohne Weg zurück. Ein einzelner Plan liess sich nicht weitergeben, und ohne Datei ging gar nichts. Die Prüfung kannte nur Typen und Referenzen, ein von Hand verändertes File konnte Werte in die Datenbank bringen, die die App nie schreibt.

## Entscheid
- **Plan teilen = Vorlage** (mit dem Nutzer entschieden): Name, Wochentage, Übungen mit Sätzen, Wiederholungen und Pause. Nie Trainings oder Verlauf, keine ids oder Zeitstempel des Absenders. Optional, per Schalter beim Teilen, und nur angeboten, wenn der Plan sie hat: **Notizen** (Text), **Fotos** der Notizen, **Gewichtsschritte**.
- **Format** `{ app: 'grynd', kind: 'plan', version: 1, exportedAt, plans: [...], notes: [...], weightSteps: [...] }`. `plans` ist eine Liste, damit später mehrere Pläne in eine Datei passen; die UI teilt einen.
- **Als Code oder Datei** (mit dem Nutzer entschieden). Code = `GRYND1:` + base64url des mit `CompressionStream('deflate-raw')` gepackten JSON, ohne neue Abhängigkeit. Er wird mit einem kurzen Text («Mein Grynd-Plan …, unter Pläne → Plan importieren einfügen») geteilt; der Import findet den Code irgendwo im eingefügten Text. Mit Fotos wird der Code zu lang, dann gibt es nur die Datei. Entpackt wird höchstens 1 MB.
- **Plan importieren fügt immer hinzu**, nichts wird überschrieben: neue UUIDv7, ein vergebener Name wird zu «Push (2)», Notizen nur für Übungen ohne eigene Notiz (Text oder Fotos), Gewichtsschritte nur für Einheiten ohne eigenen Wert. Strenge Prüfung mit den Grenzen des Editors (Sätze 1–20, Wiederholungen 1–100 und min ≤ max, Pause 0–600 s, Name 1–60 Zeichen, Wochentage 0–6, 1–50 Übungen, Notiz ≤ 500 Zeichen, ≤ 6 Fotos, Schritte aus `WEIGHT_STEPS`), Übungen nur aus dem Katalog.
- **Eine Import-Sheet für alles** (`ImportSheet`): «Datei wählen» oder Code/JSON einfügen. Erst nach dem Lesen steht fest, was es ist (geteilter Plan oder Backup). Fehler stehen direkt unter dem Feld, die Sheet bleibt offen. Einstiege: Pläne («Plan importieren», ghost, unter «Neuer Plan» und im Leerzustand, damit der Screen ohne Primary bleibt) und Einstellungen («Importieren»). Teilen: Icon-Button im Kopf des Plan-Details neben «Bearbeiten».
- **Backup-Vorschau:** Vor dem Import zeigt der Dialog Datum der Sicherung und die Anzahl Pläne, abgeschlossene Trainings, Notizen und Fotos.
- **Zusammenführen oder ersetzen** (mit dem Nutzer entschieden), Zusammenführen ist der Standard, «Alles ersetzen» destruktiv. Zusammenführen vergleicht pro Zeile die id (UUIDv7 vom Gerät, das die Zeile angelegt hat, also derselbe Plan auf zwei Geräten = eine Zeile); die neuere `updatedAt` gewinnt, bei Gleichstand bleibt die Zeile des Geräts. Soft Deletes reisen wie jede Änderung mit, es wird nie etwas weggelassen, Referenzen bleiben ganz. Zwei Regeln halten die Unique-Indizes: Von zwei lebenden Notizen oder Einstellungen derselben Übung bleibt die neuere, die andere wird gelöscht. Von zwei aktiven Trainings bleibt das des Geräts aktiv, das andere wird als `aborted` gespeichert.
- **Rückgängig:** Vor jedem Import (Backup oder Plan) wird der Stand im Speicher gehalten; der Erfolgs-Toast bietet 10 s lang «Rückgängig». Nur der letzte Import lässt sich rückgängig machen, ein neuer Import schliesst den alten Toast (ein älterer Stand würde den neueren Import mit verwerfen). Nicht auf Platte, das wäre mehr UI für einen seltenen Fall.
- **Strengere Backup-Prüfung:** Jede Spalte hat eine Regel: UTC-Zeitstempel (ISO 8601), erlaubte Werte (`status`, `isExtra`), Bereiche, Wochentage als JSON-Liste 0–6 ohne Doppelte, eindeutige ids, höchstens ein aktives Training, eine lebende Notiz und Einstellung pro Übung, höchstens 6 Fotos pro Übung, Foto ≤ ~5 MB. Die Grenzen sind so streng wie das, was die App schreibt, aber nicht strenger als die Datenbank: Grenzen, die nur die UI setzt, sind grosszügig (z. B. 99 Sätze statt 20), damit ältere Sicherungen nie abgelehnt werden. Unbekannte Übungen haben eine eigene Meldung («App aktualisieren»), Dateien über 200 MB werden nicht gelesen.
- **Dateiname** der Sicherung mit Uhrzeit (`grynd-backup-2026-10-14-0930.json`), geteilte Pläne als `grynd-plan-<name>.json`.

## Umsetzungshinweise
- `core/backup/backup.ts`: Spaltenregeln in `BACKUP_TABLES`, `summarizeBackup()`; `core/backup/merge.ts`: `mergeBackups()` (rein, getestet). `BackupService.import(backup, mode)` baut beim Zusammenführen den gemeinsamen Stand im Speicher und spielt ihn über `restore()` in einer Transaktion ein; zurück kommt der alte Stand für «Rückgängig».
- `core/share/`: `plan-share.ts` (Format, Prüfung, Namen), `share-code.ts` (Code), `PlanShareService` (erstellen, importieren; Fotos werden vor der Transaktion geschrieben und bei einem Fehler entfernt), `ImportReader` (Datei oder Text → Backup, Plan oder Fehler), `ShareService` (App: Teilen-Menü; Browser: Download, Teilen-Menü oder Zwischenablage).
- `shared/components/import-sheet/`: `ImportSheet` und `ImportFlow` (Vorschau, Import, Rückgängig). `shared/components/plan-share/`: `PlanShareSheet`.
- `CompressionStream('deflate-raw')` gibt es in Android-WebViews ab Chrome 103 und unter iOS ab 16.4. Auf älteren Geräten scheitert «Als Code teilen» mit einer Meldung, die Datei geht immer.
- Figma hat keine Frames dafür (nur Code). Vorschau: `/dev/components`.
