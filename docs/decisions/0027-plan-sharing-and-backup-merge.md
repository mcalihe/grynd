# 0027 – Export nach Wahl, Pläne als Vorlage, Backup zusammenführen, strengere Prüfung

**Datum:** 2026-10-14 · **Status:** entschieden (ergänzt [0013](0013-settings-units-swipe-backup.md): Import ersetzt nicht mehr zwingend alles)

## Kontext
Bisher gab es nur das volle Backup in den Einstellungen: alle Daten als JSON-Datei, beim Import nach einer allgemeinen Rückfrage komplett ersetzt, ohne Weg zurück. Ein einzelner Plan liess sich nicht weitergeben, und ohne Datei ging gar nichts. Die Prüfung kannte nur Typen und Referenzen, ein von Hand verändertes File konnte Werte in die Datenbank bringen, die die App nie schreibt.

## Entscheid
- **Ein Export-Sheet** (`ExportSheet`, mit dem Nutzer entschieden), Gegenstück zum Import-Sheet: oben die Auswahl, darunter der Code und die zwei Wege. **Pläne:** «Alle» oder einzelne ankreuzen. **Mitnehmen** (Schalter): Trainings (Verlauf), Notizen, Fotos (nur mit Notizen), Gewichtsschritte. Aus dem Plan-Detail (Teilen-Icon neben «Bearbeiten») ist dieser Plan allein gewählt, ohne Verlauf und Fotos; aus den Einstellungen («Exportieren») alles.
- **Was entsteht, hängt am Verlauf** (mit dem Nutzer entschieden). **Ohne Verlauf: Vorlage** `{ app: 'grynd', kind: 'plan', version: 1, exportedAt, plans: [...], notes: [...], weightSteps: [...] }` mit Name, Wochentagen und Übungen (Sätze, Wiederholungen, Pause, bei Cardio die Zieldauer nach [0025](0025-cardio-and-calories.md)), ohne ids oder Zeitstempel; beim Import kommen die Pläne als Kopie dazu, das passt zum Weitergeben an andere. **Mit Verlauf: Backup** der gewählten Pläne (`selectBackup()`): ihre Zeilen, ihre Trainings mit allem darunter (auch Soft Deletes, damit Löschungen beim Zusammenführen mitkommen), Notizen, Fotos und Einstellungen nur der Übungen, die darin vorkommen. Neues Feld `complete`: nur alle Pläne mit allen Schaltern ergeben ein vollständiges Backup; ältere Dateien ohne das Feld gelten als vollständig.
- **Code kopieren oder Datei speichern** (mit dem Nutzer entschieden), kein Teilen-Menü mit Begleittext. Code = `GRYND1:` + base64url des mit `CompressionStream('deflate-raw')` gepackten JSON, ohne neue Abhängigkeit. Er steht im Sheet in einem Feld und wird bei jeder Änderung der Auswahl neu gebaut, damit «Code kopieren» ihn noch während des Taps in die Zwischenablage schreibt (iOS erlaubt sie nur dort; sonst Rückfall auf markieren und `execCommand('copy')`). Mit Fotos gibt es keinen Code, nur die Datei. Entpackt wird höchstens 50 MB (Verlauf passt, eine Code-Bombe nicht). **Datei:** im Browser ein Download, in der App das System-Menü zum Sichern oder Senden (Android und iOS ohne Speicher-Berechtigung).
- **Plan importieren fügt immer hinzu**, nichts wird überschrieben: neue UUIDv7, ein vergebener Name wird zu «Push (2)», Notizen nur für Übungen ohne eigene Notiz (Text oder Fotos), Gewichtsschritte nur für Einheiten ohne eigenen Wert. Strenge Prüfung mit den Grenzen des Editors (Sätze 1–20, Wiederholungen 1–100 und min ≤ max, Pause 0–600 s, Zieldauer leer oder 1 s–23:59:59 (fehlt sie in älteren Dateien, gilt leer), Name 1–60 Zeichen, Wochentage 0–6, 1–50 Übungen, Notiz ≤ 500 Zeichen, ≤ 6 Fotos, Schritte aus `WEIGHT_STEPS`), Übungen nur aus dem Katalog.
- **Eine Import-Sheet für alles** (`ImportSheet`): «Datei wählen» oder Code/JSON einfügen. Erst nach dem Lesen steht fest, was es ist (geteilter Plan oder Backup). Fehler stehen direkt unter dem Feld, die Sheet bleibt offen. Einstiege: Pläne («Plan importieren», ghost, unter «Neuer Plan» und im Leerzustand, damit der Screen ohne Primary bleibt) und Einstellungen («Importieren»). Eine Vorlage wird hinzugefügt, ein Backup zusammengeführt; «Alles ersetzen» gibt es nur für ein vollständiges Backup, ein Teil-Export würde sonst alles löschen, was er weglässt.
- **Backup-Vorschau:** Vor dem Import zeigt der Dialog Datum der Sicherung und die Anzahl Pläne, abgeschlossene Trainings, Notizen und Fotos.
- **Zusammenführen oder ersetzen** (mit dem Nutzer entschieden), Zusammenführen ist der Standard, «Alles ersetzen» destruktiv. Zusammenführen vergleicht pro Zeile die id (UUIDv7 vom Gerät, das die Zeile angelegt hat, also derselbe Plan auf zwei Geräten = eine Zeile); die neuere `updatedAt` gewinnt, bei Gleichstand bleibt die Zeile des Geräts. Soft Deletes reisen wie jede Änderung mit, es wird nie etwas weggelassen, Referenzen bleiben ganz. Drei Regeln halten die Unique-Indizes: Von zwei lebenden Notizen oder Einstellungen derselben Übung und von zwei offenen Pausen ([0023](0023-pause-workout.md)) desselben Trainings bleibt die neuere, die andere wird gelöscht. Von zwei aktiven Trainings bleibt das des Geräts aktiv, das andere wird als `aborted` gespeichert.
- **Rückgängig:** Vor jedem Import (Backup oder Plan) wird der Stand im Speicher gehalten; der Erfolgs-Toast bietet 10 s lang «Rückgängig». Nur der letzte Import lässt sich rückgängig machen, ein neuer Import schliesst den alten Toast (ein älterer Stand würde den neueren Import mit verwerfen). Nicht auf Platte, das wäre mehr UI für einen seltenen Fall.
- **Strengere Backup-Prüfung:** Jede Spalte hat eine Regel: UTC-Zeitstempel (ISO 8601), erlaubte Werte (`status`, `isExtra`), Bereiche (auch für die Cardio-Spalten aus Schema 6, die als optional gelten), Wochentage als JSON-Liste 0–6 ohne Doppelte, eindeutige ids, höchstens ein aktives Training, eine offene Pause pro Training, eine lebende Notiz und Einstellung pro Übung, höchstens 6 Fotos pro Übung, Foto ≤ ~5 MB. Die Grenzen sind so streng wie das, was die App schreibt, aber nicht strenger als die Datenbank: Grenzen, die nur die UI setzt, sind grosszügig (z. B. 99 Sätze statt 20), damit ältere Sicherungen nie abgelehnt werden. Unbekannte Übungen haben eine eigene Meldung («App aktualisieren»), Dateien über 200 MB werden nicht gelesen.
- **Dateinamen** mit Uhrzeit: `grynd-backup-2026-10-14-0930.json` (vollständig), `grynd-export-…` (Teil mit Verlauf), `grynd-plans-…` (mehrere Vorlagen), ein einzelner Plan als `grynd-plan-<name>.json`.

## Umsetzungshinweise
- `core/backup/backup.ts`: Spaltenregeln in `BACKUP_TABLES`, `selectBackup()`, `summarizeBackup()`; `core/backup/merge.ts`: `mergeBackups()` (rein, getestet). `BackupService.import(backup, mode)` baut beim Zusammenführen den gemeinsamen Stand im Speicher und spielt ihn über `restore()` in einer Transaktion ein; zurück kommt der alte Stand für «Rückgängig».
- `core/share/`: `plan-share.ts` (Format, Prüfung, Namen), `share-code.ts` (Code), `PlanShareService` (erstellen, importieren; Fotos werden vor der Transaktion geschrieben und bei einem Fehler entfernt), `ImportReader` (Datei oder Text → Backup, Plan oder Fehler), `ExportService` (Auswahl → JSON, Dateiname, Code), `ShareService` (Datei: App-Menü oder Download; Code: Zwischenablage).
- `shared/components/import-sheet/`: `ImportSheet` und `ImportFlow` (Vorschau, Import, Rückgängig). `shared/components/export-sheet/`: `ExportSheet` mit helm `hlm-checkbox` (neu generiert).
- `CompressionStream('deflate-raw')` gibt es in Android-WebViews ab Chrome 103 und unter iOS ab 16.4. Auf älteren Geräten gibt es keinen Code (Meldung «Export fehlgeschlagen»), die Datei geht immer.
- Seit [0023](0023-pause-workout.md) erreicht man mit pausiertem Training die Einstellungen, ein Import kann also auf ein laufendes Training treffen. Das deckt die Regel für aktive Trainings ab; danach lädt `WorkoutService.restore()` den Stand neu.
